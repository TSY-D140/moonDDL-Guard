# Enum and type evolution

`moon run engine/cli -- specimens/enum-evolution.sql --transaction=autocommit --delivery=statements --json` reviews an enum extension, explicit commit boundary, seed write and coordinated label rename. The example is a project-owned migration pattern, not a copied production migration. Readers must tolerate new values before writers enable them.

The bounded PostgreSQL 18 grammar covers CREATE TYPE name AS ENUM (0–128 distinct labels), ALTER TYPE ADD VALUE [IF NOT EXISTS] label [BEFORE|AFTER label], RENAME VALUE old TO new, RENAME TO unqualified-name and SET SCHEMA unqualified-schema. Labels preserve case, spaces and empty strings, and must fit 63 UTF-8 bytes; type/schema names use the existing 63-byte identifier profile. The per-statement token limit is 512. Composite/range/base-type definitions, attribute alterations, owner/options and arbitrary type DDL remain incomplete.

PG921 retains unresolved catalog/privilege/dependency conditions. PG922 warns that enum lifecycle/order cannot later be revised through a simple DROP VALUE. PG923 explicitly distinguishes permitting ADD VALUE in a transaction from using its new label before commit: active/implicit/unknown scopes warn; separately synchronized known autocommit is advisory. PostgreSQL has exceptions for newly-created types; this static profile deliberately makes no exception inference or symbolic type/value catalog. It does not prove whether a later cast, literal/default or arbitrary function uses a newly-added value. PG924 covers forward compatibility and IF NOT EXISTS placement assumptions, PG925 existing-row textual changes on label rename, PG926 explicit ordering/comparison concerns, and PG927 type-name/schema cutover. RENAME VALUE preserves ordering.

Tests cover context combinations, UTF-8 and count bounds, retained malformed input, recovery, deterministic SARIF and report/delta replay. `checks/postgres.mbtx` checks actual existing-type use-before-commit rejection, label rename and successful use after a separately committed ADD VALUE. These are domain semantics tests, not a general PostgreSQL parser or production data check.

References checked 2026-10-30: [CREATE TYPE](https://www.postgresql.org/docs/18/sql-createtype.html), [ALTER TYPE](https://www.postgresql.org/docs/18/sql-altertype.html) and Squawk's [rule catalog](https://squawkhq.com/docs/). Implementation, tests and fixture are Apache-2.0 and contain no copied upstream source/tests.
