# New tables and seed data

Run `moon run engine/cli -- specimens/bootstrap.sql --transaction=autocommit --delivery=statements --json`. This workflow reviews new tables and repeatable reference-data writes before your own migration runner executes them; it never executes or rewrites SQL.

CREATE TABLE accepts regular, TEMP/TEMPORARY or UNLOGGED definitions with optional IF NOT EXISTS, at most 128 column/constraint elements, 1024 tokens and nesting 32. Columns reuse the bounded type/default/identity/serial/generated-expression profile. One inline PRIMARY KEY, UNIQUE, CHECK or REFERENCES clause per column, and equivalent table constraints are accepted. Explicit NOT NULL can precede or follow DEFAULT. Unknown clauses, CTAS, LIKE, inheritance, partitioning, storage/tablespace/ON COMMIT options and multiple inline constraints remain incomplete. Empty PostgreSQL tables are accepted. No old-table rewrite is inferred from a new table's columns/keys. IF NOT EXISTS does not establish schema equivalence. A new FK still affects its referenced existing relation; that lock is tracked through savepoint rollback.

Seed INSERT accepts DEFAULT VALUES or 1–100 VALUES tuples with consistent width, at most 32 columns/cells per row and 1024 tokens. It validates every active AST field, supported scalar expression, column-list uniqueness, simple conflict keys, assignments and RETURNING. ON CONFLICT DO NOTHING (optional simple column list) and DO UPDATE SET (required simple column list, optional scalar WHERE) receive separate retry/locking diagnostics. Duplicate canonical target columns/assignments or inconsistent row widths are rejected as incomplete input. SQLGlot's parsed source is not exported as a schema API.

PG821 covers locks, defaults, generated/identity rules, triggers/RLS and constraints. PG822 distinguishes skipped stale seed values from updating conflicts, duplicate-key cardinality failures and locks retained even when DO UPDATE WHERE skips updates. PG803/804 connect seeds to prior blocking DDL and transaction duration. PG807 covers RETURNING's missing/skipped rows and sensitive output. No catalog resolution, data equality, input-key uniqueness or actual affected-row bound is certified. Sequence consumption on conflicts/failures need not roll back.

INSERT SELECT, writable/general CTEs, target aliases, OVERRIDING, ON CONSTRAINT, expression/partial conflict targets, tuple assignments, arbitrary functions/subqueries and PG18 RETURNING WITH aliases remain unassessed. Use the incomplete exit code 2 to require manual review of these forms.

Tests: `engine/create_table_test.mbt`, `engine/seed_insert_test.mbt`; portable CLI/replay fixture: `specimens/bootstrap.sql`; PostgreSQL semantics: `checks/postgres.mbtx`. Fixture and tests were authored for this repository under Apache-2.0. Semantics follow [CREATE TABLE](https://www.postgresql.org/docs/18/sql-createtable.html) and [INSERT](https://www.postgresql.org/docs/18/sql-insert.html); no upstream implementation or test was copied.
